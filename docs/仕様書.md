# 仕様書

このツールの処理仕様（保守する人向け）。コーディング規約は comken リポジトリの
`CONVENTIONS.md` に従う。

---

## 1. 目的・概要

Salesforce のレポートを**1本のツールでまとめて落とし、使う側が読みに行くフォルダへ直接置く**。

各プロジェクトが個別に取りに行くと、同じレポートを何度も叩き、認証情報の登録先も
プロジェクトの数だけ増え、1つで取得が失敗するとそこだけ動かなくなる。取得をここへ集める。

**使う側は取得の手段を知らない。** 置かれたファイルを読むだけなので、取得が失敗した日は
人が同じ名前で置けば後続はそのまま動く。

---

## 2. 処理フロー

```
レポート一覧.csv を読む
  ↓
すでに今日のファイルが置かれている行を飛ばす（手で置いたものを上書きしない）
  ↓
URL のドメインから組織を引き、組織ごとにまとめる（認証は組織につき1回）
  ↓
組織ごとに接続 → レポートを実行 → 置き場所へ CSV で書く
  ↓
結果の内訳をログに出す。失敗があれば DownloadFailedError で止める
```

---

## 3. 入出力

| 種別 | 内容 | 場所 |
|---|---|---|
| 入力 | 管理表（名前・レポートURL・置き場所） | `レポート一覧.csv`（プロジェクト直下・`.gitignore`） |
| 入力 | client_id / client_secret | DPAPI（`comken.credentials`。`sandbox_client_id` など） |
| 出力 | レポートの明細 | 管理表の「置き場所」／`名前_YYYYMMDD.csv` |
| 出力 | 実行の記録 | `logs/YYYY-MM-DD.log` |
| 出力 | API の計測（回数・エラー・リトライ・秒数・消費量） | `logs/API計測.csv`（追記） |

---

## 4. 設定

**config.ini は置かない。** 変えるのは管理表の中身であって、管理表の場所ではないため。
非エンジニアが変える値は、すべて `レポート一覧.csv` に集まっている。

---

## 5. 設計判断

### 何を落とすかをコードに書かない

レポートは増える。増えるたびにコードを直す形にすると、そのたびに配置が要る。
管理表に1行足すだけで済むようにする。

### 管理表にはレポート URL をそのまま貼る

レポート ID（`00O...`）だけを人が抜き出す工程を挟むと、そこで写し間違いが起きる。
`report_id_from_url()` が URL から取り出す。ID を直接書いても動く。

### 組織を選ぶ列は作らない

接続先は URL のドメインで決まる（`site_for()`）。人が選ぶ列を作ると、URL と食い違ったときに
**別の組織へ問い合わせて「レポートが見つからない」**という分かりにくい失敗になる。
未登録のドメインは `SalesforceSiteNotFoundError` で止まり、黙って別組織へはつながらない。

### 中間の受け渡しフォルダを挟まない

「集約してから配る」2段にしても、管理表の置き場所に**使う側のフォルダを直接書けば済む**。
同じレポートを2つのプロジェクトが使うときは、行を2つ書いて2回落とす。
Salesforce を2回叩くが、配布の処理を1段増やすよりも仕組みが減る。

### すでに置かれていれば取りに行かない

落とし直しを省くためだけでなく、**人が手で置いたファイルを上書きしないため**。
これがあるので「失敗した分を手で置いて、もう一度実行する」が成立する。

### 1件失敗しても残りは続ける

5本のうち1本が落ちたときに全部やり直すと、手で用意する手間が5本ぶんになる。
組織ごと落ちた場合も、その組織の**まだ手を付けていない行だけ**を失敗にする。

### 失敗は行で数える（名前ではなく）

同じレポートを2か所へ置くときは**同じ名前の行が2つ並ぶ**。名前で数えると片方しか
報告されず、手で置く場所も1つしか出ない。

### 0 行は成功にしない

空の CSV を置くと、使う側は「データが無い日」と「取得が失敗した日」を区別できない。

### 置き場所のフォルダが無ければ作らない

無いのは書き間違いのことが多い。勝手に作ると、誰も読まない場所へ置き続けてしまう。

### 失敗があれば最後に例外で止める

ログだけに出して正常終了すると、RPA 基盤から見て成功と区別が付かない。
途中で続けたぶん、終わりに必ず報せる。

### 計測は失敗した実行でも残す

`_record_metrics()` は `finally` で呼ぶ。**問題が起きたときにこそ**、どこで時間がかかったか・
リトライが何回起きたかを知りたい。1本ごとの所要時間は `Timer` でログに出す。

## 6. 構成

```
main.py              エントリポイント（ログ初期化・エラー受け）
レポート一覧.csv      管理表（.gitignore。example をコピーして作る）
実行.bat             起動用（ダブルクリック）
認証情報の登録.bat    DPAPI へ client_id / client_secret を登録する画面
src/run.py           処理の本体
docs/                使い方.md（操作手順）・仕様書.md（この文書）
logs/                実行の記録と API 計測（.gitignore）
```

comken は共有サーバーを直接参照する（`実行.bat` が起動時に `PYTHONPATH` を設定）。

---

## 7. 例外

| 例外 | いつ | 対処 |
|---|---|---|
| `EmptyReportError` | 明細が 0 行だった | 本当に 0 件なら空の CSV を手で置く |
| `DestinationFolderNotFoundError` | 置き場所のフォルダが無い | 管理表の「置き場所」を直す／共有フォルダの接続と権限を見る |
| `DownloadFailedError` | 1件以上落とせなかった | メッセージの場所へ手で置いて再実行する |
| `SalesforceSiteNotFoundError` | URL のドメインが未登録 | URL を見直す。新しい組織なら comken に組織クラスを足す |
| `SalesforceConnectionError` | 接続・タイムアウト（60 秒） | ネットワークと Salesforce の状態を見る |

---

## 8. 実行方法

- 通常: `実行.bat` をダブルクリック（または `python main.py`）
- 社内 RPA 基盤から: `main.py` 末尾のコメントのとおり `backoffice(main, PROJECT_NAME)` に差し替える
